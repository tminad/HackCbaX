# MVP_SPEC.md — Autonomous LATAM Carry Agent

## 1. Problem

Retail users can access multiple currencies and DeFi protocols, but deciding where to place money requires understanding:

- interest/yield
- temporary incentives
- currency depreciation/appreciation
- volatility
- liquidity
- swap fees
- slippage
- protocol mechanics

A high nominal APR can be worse than a lower APR if the underlying currency depreciates or if moving capital costs too much.

Most users do not want to become FX or DeFi experts.

## 2. Product thesis

> Deposit once. The agent decides when and where the money should move.

The MVP automatically compares a small set of LATAM carry opportunities and only moves capital when the expected improvement is large enough to justify the execution costs.

The product is not an APY leaderboard.

The core differentiator is:

> Highest yield is not always highest return.

## 4. Key concepts

### Yield / APR
Annualized return shown by a yield strategy.

### Base APR
Return generated by the underlying lending/strategy activity.

### Incentive APR
Temporary promotional rewards.

### FX
Foreign exchange: the value of one currency relative to another.

### Expected FX Return 30d
Expected appreciation/depreciation of a local currency against USD over the next 30 days.

### FX Volatility 30d
A measure of how unstable the currency has been / is expected to be.

### Slippage
Difference between expected swap price and actual execution price.

### Liquidity
How easily capital can enter/exit without a large price impact or withdrawal problem.

### Net Carry
Expected return after considering yield, expected currency movement and a risk buffer.

## 5. Core formulas

### Incentive persistence

```text
P = min(1, incentiveDaysLeft / 30)
```

### Effective APR

```text
effectiveAPR = baseAPR + incentiveAPR * P
```

### 30-day yield

```text
yield30d = effectiveAPR * 30 / 365
```

### Risk buffer

```text
riskBuffer = fxVolatility30d * riskFactor
```

Default:

```text
riskFactor = 0.25
```

### Net Carry

```text
netCarry30d =
    yield30d
  + expectedFxReturn30d
  - riskBuffer
```

### Switching cost

```text
switchCost =
    gasCostPct
  + swapFeesPct
  + slippagePct
  + otherExecutionFeesPct
```

### Rebalance benefit

```text
netRebalanceBenefit =
    targetNetCarry30d
  - currentNetCarry30d
  - switchCost
```

### Rebalance decision

```text
shouldRebalance =
  netRebalanceBenefit >= 0.20%
  AND execution conditions are safe
  AND normal cooldown has expired
```

Maximum accepted slippage for MVP:

```text
0.50%
```

Normal cooldown:

```text
12 hours
```

Critical risk can trigger emergency exit regardless of cooldown.

## 6. Why switching costs are NOT part of Net Carry

Net Carry answers:

> Which strategy is intrinsically more attractive over the next 30 days?

ShouldRebalance answers:

> Given where the money is right now, is the better strategy sufficiently better to justify moving?

Keeping them separate prevents route-specific execution costs from contaminating the strategy ranking.

## 7. Why liquidity is a filter

Do not assign an arbitrary number like:

```text
liquidity score = 73
```

Instead, determine whether the requested action is executable.

Examples:
- Can the current vault satisfy the withdrawal?
- Can the target vault accept the position?
- Is a swap route available?
- Is estimated slippage below 0.50%?

If not, the strategy is not eligible.

## 8. Example

Assume:

### BRAt current position

```text
effective APR: 12%
30d yield: +0.99%
expected BRL/USD return: -0.20%
risk buffer: -0.20%

Net Carry 30d = +0.59%
```

### ARGt candidate

```text
effective APR: 17%
30d yield: +1.40%
expected ARS/USD return: -0.45%
risk buffer: -0.25%

Net Carry 30d = +0.70%
```

ARGt is intrinsically better:

```text
+0.70% - +0.59% = +0.11%
```

But suppose switching costs are:

```text
0.15%
```

Then:

```text
netRebalanceBenefit =
0.70% - 0.59% - 0.15%
= -0.04%
```

Decision:

```text
HOLD BRAt
```

This is a successful intelligent decision.

Now suppose ARGt Net Carry becomes:

```text
+1.10%
```

Then:

```text
1.10% - 0.59% - 0.15%
= +0.36%
```

Safety margin is:

```text
+0.20%
```

Decision:

```text
REBALANCE TO ARGt
```

## 9. Suggested domain types

```ts

type StrategySnapshot = {
  asset: Asset;

  baseApr: number;

  fxVolatility30d: number;

```

## 11. Tests that must exist

At minimum:

### Net Carry
- no incentives
- incentive lasts all 30 days
- incentive expires after 15 days
- negative FX return
- positive FX return
- different risk factors

### Eligibility
- excessive slippage
- unavailable route
- withdrawal unavailable
- critical risk

### ShouldRebalance
- target worse than current
- target slightly better but costs erase benefit
- target better but below safety margin
- target sufficiently better
- cooldown active
- emergency exit overrides cooldown

Use deterministic fixtures.

## 13. Product pitch

Problem:
A high interest rate can be completely erased by currency depreciation and execution costs.

Solution:
An autonomous agent evaluates yield, currency risk, liquidity and switching costs, then moves capital only when the expected improvement is meaningful.

Core line:

> The highest rate is not always the highest return.

Alternative:

> Deposit once. The agent decides when your money should move.

## 14. MVP success criteria

The MVP is successful if the jury can watch, in one live flow:

1. a deposit/start action
2. three strategy comparisons
3. a non-trivial decision
4. transparent math
5. autonomous deployment or simulated execution backed by real integration
6. a changed market condition
7. a ShouldRebalance decision
8. either HOLD for a good reason or an automatic rebalance
9. at least one real onchain interaction if available

That is more valuable than many incomplete features.
